ConteneurisationUne image petite, sans shell, non-root

# 1. Compilation
FROM golang:1.27.2-alpine AS build
RUN CGO_ENABLED=0 go build -o /out/api .

# 2. Exécution : seulement le binaire
FROM gcr.io/distroless/static-debian12
COPY --from=build /out/api /api
USER 65532:65532
ENTRYPOINT ["/api"]
  • Multi-étapes : les outils de compilation ne partent pas en production
  • Distroless : environ 30 Mo, pas de shell → moins de surface d'attaque
  • UID numérique : Kubernetes peut vérifier runAsNonRoot
  • docker compose up : API + Prometheus + Grafana + Jaeger

KubernetesToujours 2 copies, et il se répare tout seul

  • Deployment : 2 réplicas, mise à jour progressive sans coupure
  • Sondes sur /health : readiness (prêt à recevoir du trafic ?) et liveness (encore vivant ?)
  • Ressources : requêtes et limites CPU/mémoire
  • Sécurité : non-root, système de fichiers en lecture seule, aucune capability
  • Service ClusterIP + ConfigMap, appliqués avec Kustomize

Observabilité · logs et métriquesVoir ce qui se passe, en direct

Logs JSON

Une ligne par requête : route, statut, durée, request_id, trace_id. Le niveau suit le statut : INFO, WARN, ERROR.

Métriques Prometheus

/metrics : nombre de requêtes, histogramme des temps de réponse, requêtes en cours, par route.

SRE

p95 = SLI. Un SLO possible : 95 % des requêtes en moins de 200 ms.

Observabilité · tracingSuivre une requête de bout en bout

  • OpenTelemetry : un span par requête, nommé d'après sa route
  • Envoyé en OTLP à Jaeger
  • En-tête traceparent entrant poursuivi
  • Corrélation : le trace_id du log ouvre la trace dans Jaeger

Logs = quoi · Métriques = combien, à quelle vitesse · Traces = par où

BilanLeçons apprises

  • Automatiser révèle des problèmes invisibles à l'œil : des failles dans la version même de Go
  • Vérifier les outils : gosec ne lisait pas Go 1.27 et a dû tourner avec Go 1.26
  • Kubernetes est strict : runAsNonRoot exige un UID numérique
  • Petits incréments : une PR par tâche, des erreurs petites et faciles à corriger
